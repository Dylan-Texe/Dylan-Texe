**001 · Windows Infrastructure Lab**  
Simulated small-business environment on KVM/libvirt (`corp.lab`). DC01 runs Windows Server 2022 as AD DS / DNS / DHCP. CLIENT01 is domain-joined. Live-verified: domain promote, reverse DNS, OUs, groups, baseline GPO, domain auth. Remaining service work is documented as reconstruction steps after the host hit RAM/CPU limits.

**002 · Networking Lab**  
Vendor-neutral network lab covering OSI/TCP-IP, IPv4/IPv6, DHCP, DNS, NAT, VLANs, routing, firewalls, segmentation, and packet-level troubleshooting. Validation model:

`interface → address → gateway → DNS → route → port → application`

**003 · PowerShell IT Toolkit**  
Small, independently testable scripts for inventory, network/service health, local users, event collection, and CSV export. Results are structured PASS / CHECK / FAIL objects, not pretty text. Includes a smoke-test workflow and transcript logging.

**004 · Linux Infrastructure Lab**  
Core lab is established. Filesystem, processes, networking, system-health inspection, and a failure-exercise framework are in. Next: users/groups, SSH, storage, systemd, Bash/Python automation, hardening, recovery.

**Meridian**  
Choropleth world atlas. Switch HDI, GDP per capita, life expectancy, population density, CO₂ per capita, and internet users. Hover for rank, click for a country profile.

**Network Monitor** *(planned)*  
Host reachability, latency, packet loss, service/port checks, alerting vs diagnosis, historical reporting, failure simulation.

**IoT Environment Monitor** *(planned)*  
Raspberry Pi 3B + Arduino with DHT11, PIR, and ultrasonic sensors. Bring-up, calibration, serial transfer, invalid-reading handling, logging.

**AI Troubleshooting Assistant** *(planned)*  
Keeps the human operator in control. Separates evidence, hypotheses, and confirmed findings. Local models where they earn their place. Recommendations must be testable against observable system evidence.

**Legacy Projects**  
Incomplete work stays. Each archive entry should record what it was, why it was built, what worked, what failed, and what was learned.


I prefer evidence over assumptions, and reproducible results over screenshots of a working state.

A system that only works once has not been understood. A failure that has been reproduced, isolated, and written down is more useful than a silent success.

Diagnosis runs from the bottom up. Connectivity at one layer is not proof of the layers above it.

## Lab philosophy

The lab is built around available hardware and constrained resources. Virtualisation, lightweight services, simulation, and existing equipment come before buying more hardware.

The Windows lab was paused when the host ran out of RAM and CPU — and that pause is part of the record. Limits are data. They get documented, not hidden.

The goal is not to collect projects. It is to build a connected body of practical knowledge where each system feeds experience, tooling, and lessons into the next.

**Failure is a first-class lab activity.** Break it on purpose, on an isolated system, then recover it. If you cannot recover it, you did not finish the exercise.
